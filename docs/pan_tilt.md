# pan_tilt.py — 팬틸트 서보 제어

## 역할

Pi 카메라가 올라간 팬틸트(Arducam B0283)의 서보 2개를 움직인다. 웹의 방향 버튼(↑↓←→), 이동 각도 선택(1°~20°), Center 버튼이 여기를 부른다.

- 채널 0 = 틸트(위아래), 채널 1 = 팬(좌우)
- 마지막 위치를 `servo_state.json`에 저장해서, 프로그램을 다시 켜도 그 위치에서 시작한다.
- 목표 각도로 한 번에 보내지 않고 **부드럽게(천천히 출발, 천천히 멈춤)** 움직인다.

## 코드 구조

| 이름 | 하는 일 |
|---|---|
| `MIN_PULSE`, `MAX_PULSE` | 각도 0과 90에 대응하는 펄스 길이 (PCA9685 tick) |
| `_duration(distance)` | 이동 거리에 맞는 이동 시간 (0.3~1.0초) |
| `_ease(t)` | 진행률 0~1을 "천천히 출발, 천천히 멈추는" 곡선으로 바꿈 |
| `_Axis` | 축 하나의 상태: 지금 보내는 각도, 목표, 출발 각도·시각, 이동 시간 |
| `PanTiltServo` | PCA9685 초기화, 위치 저장/복원, 이동 스레드, 외부 API |

외부 API (`app.py`가 부름):
- `get_pan_angle()`, `get_tilt_angle()`: **목표** 각도를 돌려줌. 버튼을 연달아 누르면 이전 목표에 더해지게 하려고 현재 위치가 아니라 목표를 준다.
- `set_pan_angle(angle)`, `set_tilt_angle(angle)`: 목표만 바꾸고 바로 돌아옴. 실제 움직임은 백그라운드 스레드가 한다.
- `last_move`: 마지막으로 펄스를 보낸 시각. 움직임 감지가 "카메라를 돌리는 중"인지 판단하는 데 씀.

## 사용 라이브러리와 선택 이유

| 라이브러리 | 용도 | 선택 이유 |
|---|---|---|
| **adafruit-circuitpython-pca9685** | PCA9685 레지스터 제어 | 팬틸트 보드가 PCA9685(I2C 0x40)를 씀. 채널별 `duty_cycle`만 쓰면 돼서 간단 |

## 동작 원리

### 1. 서보는 펄스 길이로 각도를 정한다

취미용 서보는 20ms(50Hz)마다 한 번씩 오는 펄스의 **길이**를 보고 축의 위치를 정한다. 펄스가 길수록 한쪽으로, 짧을수록 반대쪽으로 돈다. 이 프로젝트는 600μs ~ 2400μs를 쓴다.

### 2. PCA9685로 펄스 만들기

PCA9685는 PWM 신호를 만드는 칩이다. 한 주기(50Hz면 20,000μs)를 4096칸(12bit)으로 나눠서, 몇 칸 동안 신호를 켤지 정한다.

```
1 tick = 20,000μs / 4096 ≈ 4.88μs
600μs  → 600 × 4096 / 20000 ≈ 123 tick   (MIN_PULSE)
2400μs → 2400 × 4096 / 20000 ≈ 492 tick  (MAX_PULSE)
```

코드의 각도(0~90)를 이 사이에 직선으로 대응시킨다.

```python
pulse = MIN_PULSE + (angle / 90.0) * (MAX_PULSE - MIN_PULSE)   # tick
duty_cycle = int((pulse / 4096.0) * 0xFFFF)                    # 라이브러리는 16bit 값을 받음
```

예: 45° → 123 + 0.5 × 369 = 307.5 tick ≈ 1500μs (가운데).

**주의**: 코드의 각도는 실제 회전 각도와 다르다. 화면 이동량으로 재보니 명령 10°가 실제 약 17°였다 (0~90 범위가 실제 150° 이상). 처음에 서보 사양(1000~2000μs)대로 설정했더니 회전 범위가 좁아서, 900→700→600μs로 넓혀가며 시험했고 500~2500μs는 끝에서 무리가 느껴져 600~2400μs로 정했다.

### 3. 왜 부드럽게 움직이나

목표 펄스를 한 번에 보내면 서보가 최고 속도(60°당 약 0.1초)로 달려가 **급정지**한다. 팬틸트를 바닥에 단단히 고정한 뒤로 특정 각도(예: 29°)에서 그 충격 때문에 서보가 목표 근처를 계속 왔다 갔다 하는 **헌팅(떨림)** 이 생겼다. 받침대가 충격을 흡수하지 못해서 떨림이 몇 초 넘게 이어졌다.

29°에 도착한 뒤 2~6초 동안 화면이 흔들린 양을 재서 비교했다.

| 도착 방식 | 흔들림 |
|---|---|
| 한 번에 이동 | 115~174px |
| 0.6초에 걸쳐 부드럽게 | 10~12px |
| 참고: 가만히 있을 때 | 6~8px |

그래서 펄스를 20ms마다 조금씩 나눠 보낸다.

### 4. 부드럽게 움직이는 계산

진행률 `t`(0→1)를 그대로 쓰면 일정한 속도로 움직여서 출발과 도착 순간 속도가 갑자기 바뀐다. 코사인 곡선을 쓰면 속도가 0에서 시작해 가운데서 가장 빠르고 다시 0으로 끝난다.

```python
def _ease(t):
    return 0.5 - 0.5 * math.cos(math.pi * t)   # t=0 → 0, t=0.5 → 0.5, t=1 → 1, 양 끝에서 기울기 0

angle = start + (target - start) * _ease(t)
```

이동 시간은 거리에 비례하되 너무 짧거나 길지 않게 자른다.

```python
duration = min(1.0, max(0.3, 0.2 + 0.04 * distance))
# 1° → 0.3초, 5° → 0.4초, 10° → 0.6초, 20° 이상 → 1.0초
```

### 5. 이동 스레드와 버튼 연타

- 버튼은 `_set_target()`만 부르고 바로 응답한다 (웹 응답 약 0.17초).
- 백그라운드 스레드(`_run`)가 20ms마다 두 축을 확인해서, 목표와 다르면 곡선에 따라 다음 각도를 보낸다.
- 움직이는 도중에 버튼을 또 누르면 **지금 보내고 있는 각도에서** 새 목표로 다시 출발한다. 5°를 세 번 빠르게 누르면 정확히 15° 이동한다.
- 두 스레드가 같은 축 상태를 바꾸므로 `Lock`으로 보호한다.

### 6. 위치 저장

목표가 바뀔 때마다 바로 파일에 쓰면 SD 카드에 자주 쓰게 된다. 마지막 변경 후 1초 동안 추가 변경이 없을 때만 저장한다(디바운스, `threading.Timer`). 켜질 때는 서보의 실제 위치를 알 수 없으므로 저장된 위치로 **바로** 보낸다 (부드럽게 출발할 기준이 없음).

## 설정값과 근거

| 상수 | 값 | 근거 |
|---|---|---|
| PWM 주파수 | 50Hz | 서보 표준. 100Hz도 시험했지만 떨림 개선이 일정하지 않음 |
| `MIN_PULSE`/`MAX_PULSE` | 123/492 (600/2400μs) | 회전 범위를 넓히되 끝에서 무리가 없는 값 |
| `STEP_INTERVAL` | 20ms | 서보가 펄스를 받는 주기(20ms)와 같게 |
| 이동 시간 | 0.3~1.0초 | 10° 이동에 0.6초로 떨림이 사라짐을 측정 |

## 시도했지만 효과가 없던 것

- **이동 후 PWM 신호 끄기**: 서보가 위치를 붙잡지 않게 하면 떨림이 멈출 거라 봤지만, 이 디지털 서보는 신호가 끊겨도 위치를 붙잡았고 오히려 더 자주 떨렸다 (6번 중 5번 vs 3번 중 1번). 되돌림.
- **펄스 값을 미세 조정해 불안정한 위치 피하기**: 한 값이 아니라 20° 근처 구간 전체가 불안정해서 효과 없음.

## 한계

- 문 닫힘 같은 외부 충격으로 시작되는 떨림은 막지 못한다. 받침대 아래 고무 패드를 권장한다.
- 서보 보드 VCC가 Pi 5V에 연결돼 있어 서보 전류가 Pi 전원을 같이 쓴다. 가끔 생기는 I2C 통신 오류(`OSError: [Errno 5]`)의 의심 원인이며, 오류가 나면 다음 갱신 때 다시 보내고 로그는 10초에 한 번만 남긴다.
