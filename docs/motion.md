# motion.py — 움직임 감지

## 역할

두 카메라(Pi, Tapo)의 화면에서 움직임을 찾아, **움직임이 있었던 분(minute)** 을 기록한다. 녹화 페이지는 이 기록으로 움직임이 있었던 10분 구간을 주황색으로 표시하고 "움직임 구간만" 볼 수 있게 한다. 24시간 녹화는 그대로 두고, 긴 녹화에서 볼 만한 곳을 찾는 용도다.

## 코드 구조

| 이름 | 하는 일 |
|---|---|
| 상수 (`CHECK_FPS`, `SIZE`, …) | 감지 설정 (아래 표) |
| `MotionLog` | 움직임이 있었던 분을 `recordings/<cam>/motion/YYYYMMDD.txt`에 한 줄씩 (`HHMM`), 같은 분은 한 번만 |
| `motion_minutes(cam, days)` | 녹화 목록용: 주어진 날짜들의 움직임 분 집합 |
| `clean_motion_logs()` | 보관 기간 지난 기록 파일 삭제 (`RecordingCleaner`가 부름) |
| `shake_compensated_ratio(prev, gray)` | 카메라 흔들림을 보정한 뒤 바뀐 픽셀 비율 계산 (핵심 알고리즘) |
| `FrameMotion` | 카메라 하나를 맡는 감지 스레드 |

`FrameMotion(cam_name, camera, mover)`는 두 카메라에 똑같이 쓴다.
- `camera`: `frame` 속성으로 최신 프레임을 주는 객체 (`picam.VideoGet`, `tapo.TapoCamera`)
- `mover`: `last_move` 속성으로 카메라를 마지막으로 돌린 시각을 주는 객체 (`pan_tilt.PanTiltServo`, `tapo.TapoCamera`)

## 사용 라이브러리와 선택 이유

| 라이브러리 | 용도 | 선택 이유 |
|---|---|---|
| **OpenCV** | 축소, 흑백, 흐림, 프레임 차이, 위상 상관, 이동 보정 | 필요한 연산이 모두 C로 구현돼 있어 라즈베리파이에서도 빠름 (비교 1번 약 9ms) |
| **NumPy** | 배열 계산 | OpenCV 이미지가 NumPy 배열 |

딥러닝 객체 인식(YOLO 등)은 쓰지 않았다. 고양이·사람 구분은 못 하지만, 라즈베리파이 4 CPU로 24시간 두 카메라를 돌리기에 부담이 거의 없고(카메라당 CPU 약 3%), 학습 데이터나 모델이 필요 없다.

## 동작 원리

### 1. 기본 아이디어: 이전 화면과 비교

움직이는 물체가 있으면 그 부분의 밝기가 바뀐다. 0.33초 전 화면과 지금 화면을 픽셀마다 빼서, 많이 바뀐 픽셀이 일정 비율 이상이면 "움직임"으로 본다.

```
1. 1280x720 프레임을 320x180으로 줄임        → 계산량 1/16, 작은 잡음은 평균되어 사라짐
2. 흑백으로 바꿈                              → 색 대신 밝기만 비교
3. 5x5 가우시안 흐림                          → 센서 잡음, 압축 잡음을 더 줄임
4. |지금 - 이전| > 25 인 픽셀을 "바뀐 픽셀"로 셈   (밝기 0~255 중 25)
5. 바뀐 픽셀 비율이 0.5% ~ 60% 사이면 움직임
```

- **0.5% 이상**: 320x180 = 57,600픽셀 중 약 290픽셀. 고양이가 움직이면 넘고, 잡음은 넘지 않는 수준. 아무 일 없을 때 측정한 변화량의 중간값은 0%였다.
- **60% 이하**: 화면 대부분이 한꺼번에 바뀌는 건 조명이 켜지거나 Tapo가 야간(적외선) 모드로 바뀐 경우라 무시한다.

### 2. 문제: 카메라가 흔들리면 화면 전체가 바뀐다

팬틸트 서보가 살짝만 떨려도 화면 전체가 몇 픽셀 밀린다. 그러면 가구 모서리, 그림자 같은 **모든 경계선**이 어긋나서 바뀐 픽셀이 1~10% 나온다. 고양이가 움직일 때와 숫자만으로는 구분이 안 된다.

### 3. 해결: 흔들림을 먼저 계산해서 맞춘 뒤 비교

**위상 상관(phase correlation)** 으로 두 화면 사이에 화면 **전체**가 얼마나 평행 이동했는지 구한다.

- 이미지를 푸리에 변환하면 "어떤 무늬가 어디에 있는지"가 위상(phase)에 담긴다. 이미지 전체가 (dx, dy)만큼 밀리면 모든 주파수의 위상이 그 이동량에 비례해 바뀐다.
- 두 이미지의 교차 파워 스펙트럼을 정규화해서 역변환하면, 이동량 (dx, dy) 위치에 뾰족한 봉우리가 생긴다. 그 위치가 화면 전체의 이동량이다. OpenCV `cv2.phaseCorrelate`가 소수점 단위까지 계산해준다.
- 화면 일부만 움직인 고양이는 봉우리에 거의 영향을 주지 않는다. 화면의 대부분(배경)이 정하는 이동량만 나온다.

```python
window = cv2.createHanningWindow((w, h), cv2.CV_32F)
(dx, dy), _ = cv2.phaseCorrelate(prev, gray, window)          # 화면 전체 이동량
aligned = cv2.warpAffine(prev, [[1, 0, dx], [0, 1, dy]], ...)  # 이전 화면을 그만큼 밀어서 맞춤
diff = |gray - aligned|  (밀려서 비교할 수 없는 가장자리는 제외)
```

**Hanning 창**: 푸리에 변환은 이미지가 상하좌우로 끝없이 반복된다고 가정해서, 화면 가장자리의 끊긴 부분이 가짜 무늬처럼 계산을 방해한다. 가운데는 1, 가장자리로 갈수록 0이 되는 창을 곱하면 이 영향이 줄어든다. 창 없이 시험했을 때는 8px 이상 흔들림이 덜 보정됐고, 창을 쓰자 20px까지 정확해졌다.

화면이 15픽셀(320x180 기준, 1280에서 60픽셀)보다 크게 밀리면 카메라를 일부러 돌린 것으로 보고 그 비교는 버린다.

### 4. 연속 확인

최근 3번(약 1초) 중 2번 이상 움직임이어야 기록한다. 한 번 툭 튀는 잡음은 무시되고, 1초 미만의 아주 짧은 움직임은 놓칠 수 있다.

### 5. 카메라를 돌리는 동안은 쉰다

웹 버튼으로 카메라를 움직이면 화면 전체가 크게 바뀐다. `mover.last_move`가 4초 이내면 비교하지 않고 이전 화면도 버린다. Pi 서보는 부드럽게 움직이는 동안 계속 `last_move`가 갱신되므로 이동이 끝날 때까지 쉰다.

### 6. 기록 방식

움직임이면 `MotionLog.mark()`가 지금 분(`HHMM`)을 파일에 한 줄 쓴다. 같은 분이면 다시 쓰지 않는다. USB가 없으면 쓰지 않는다. 녹화 목록이 각 10분 파일의 분들과 대조해 `motion: true`를 붙인다.

## 설정값과 근거

| 상수 | 값 | 근거 |
|---|---|---|
| `CHECK_FPS` | 3 | 고양이 움직임을 놓치지 않으면서 CPU 약 3% |
| `SIZE` | 320x180 | 16:9 유지, 계산량 감소 |
| `PIXEL_THRESHOLD` | 25 | 압축·센서 잡음보다 크고 물체 경계 변화보다 작음 |
| `MIN_CHANGED` | 0.5% | 잡음 상태 중간값 0%, 고양이 크기 물체 이동 시 약 0.6% |
| `MAX_CHANGED` | 60% | 조명/야간 모드 전환 무시 |
| `MAX_SHAKE` | 15px | 실제 서보 떨림(최대 약 14px@1280 = 3.5px@320)은 보정, 큰 이동은 무시 |
| `CONFIRM` | 3번 중 2번 | 일시적 잡음 제거 |
| `SETTLE_AFTER_MOVE` | 4초 | 이동 직후 흔들림이 가라앉는 시간 |

## 검증

실제 프레임을 1~20px 밀어서 흔들림을 흉내 내고 비교했다.

| 상황 | 예전 방식 (보정 없음) | 지금 방식 |
|---|---|---|
| 2~20px 흔들림 | 모두 "움직임" (0.8~17%) | 모두 "없음" (0%) |
| 고양이 크기 물체 이동 | 움직임 | 움직임 (0.63%) |
| 물체 이동 + 4~8px 흔들림 | 움직임 | 움직임 (0.64%) |

Tapo 영상 왼쪽 위 시각 표시와 Pi에 추가한 시각 표시는 감지에 영향이 없다 (변화량 최대 0.014%, 0.043%).

## 예전 방식과 바꾼 이유

처음에 Tapo는 카메라 자체 감지 결과를 ONVIF 이벤트로 받았다. 그런데 사용한 라이브러리(onvif-zeep)가 연결할 때마다 숨은 구독을 쌓아서 몇 시간 뒤 알림이 조용히 끊겼다 (`docs/troubleshooting.md` 5번). 실시간 화면용으로 이미 받는 프레임을 쓰면 부담이 거의 없고 카메라 설정에도 휘둘리지 않아서, 두 카메라 모두 같은 화면 비교 방식으로 통일했다.

## 한계

- 고양이, 사람, 그림자를 구분하지 못한다.
- 화면이 넓어진 뒤(화각 62°) 멀리 있는 물체는 작게 보여서, 멀리서 천천히 움직이면 놓칠 수 있다.
- 분 단위 기록이라 10분 파일 안의 정확한 시점은 알려주지 않는다.
